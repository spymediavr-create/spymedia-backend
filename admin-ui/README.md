# SpyMedia SNS 자동페이지

현재 흐름은 **YouTube 본편 주소 → 제목·설명·썸네일 가져오기 → 검토·수정 → Facebook·X 링크 소개 / 블로그 원고 준비**입니다. Instagram은 별도 Meta Business Suite 준비 화면을 사용합니다. 기존 홈페이지 YouTube 조회 API와 작업 이력·보관함·휴지통은 유지합니다. 이번 변경의 기준 커밋은 `335a46a69f89a3de1c40e4b724d9e918ff1364a3`입니다.

## 로컬 화면 확인

```powershell
node admin-ui/server.mjs
```

http://127.0.0.1:4310/admin/login 에서 **화면 미리보기**를 선택합니다. 루프백 전용 시안은 인증과 실제 가져오기·전송을 활성화하지 않습니다. 기존 `npm start` 서버에서는 미리보기 접근을 허용하지 않습니다.

## 현재 구현

- YouTube watch / youtu.be / shorts / live 주소에서 11자 영상 ID를 검증하고 기본 주소로 통일합니다. 임의 호스트·인증정보·포트·중복 v 인자는 거절합니다.
- 로그인·Origin·CSRF 확인 후 서버의 기존 `YOUTUBE_API_KEY`로 공식 videos.list API를 조회합니다. 공개·미등록 영상의 제목·설명과 제한된 썸네일을 가져옵니다. 비공개·삭제·할당량·일시 오류를 구분합니다. YouTube 업로드 OAuth는 이 흐름에 필요하지 않습니다.
- 가져온 결과를 먼저 보여주고 **가져온 정보 적용** 시 제목·설명을 교체합니다. 작성 중이면 교체 확인을 받습니다. 해시태그·직접 선택한 사진·수동 X 문구는 유지하며 오래된 요청 응답으로 변경된 주소를 덮어쓰지 않습니다. 원격 문자열은 HTML로 실행하지 않습니다.
- 사진은 스트리밍 보관하고 UUID·해시로 관리합니다. JPG/PNG/WebP, 한 장 8MiB, 4096×4096 이내·총 1,600만 화소 이하, 썸네일 포함 10장입니다. 파일 헤더·크기·치수를 검증하며 전체 픽셀 디코딩·재인코딩은 하지 않습니다. 영상 업로드는 이 관리자 경로에서 거절합니다.
- 새 작업은 `type=link`로 바로 준비하며 FFmpeg·FFprobe를 호출하지 않습니다. Facebook과 X에는 사진·영상 파일을 업로드하지 않습니다. 링크 카드 이미지는 각 플랫폼이 결정하며 YouTube 썸네일과 같다고 보장하지 않습니다. 블로그는 원고·URL·태그와 참고 사진 다운로드를 제공합니다.
- 다섯 채널 카드와 미리보기 탭, 지역/촬영유형, **해시태그 추천**·수동 수정은 유지합니다. YouTube는 원본, Instagram은 별도 준비로 표시합니다. X 설정이 미완료이면 미리보기·준비는 가능하고 전송 선택은 차단됩니다.
- **링크 소개 준비**는 게시하지 않습니다. 전송할 Facebook·X 작업을 선택하고 실제 제목·소개글·주소를 확인해야 전송합니다. 매 전송 전 지정 계정을 조회하고 반환된 게시 ID를 확인합니다. 토큰 존재만으로 인증 검증 완료를 표시하지 않습니다.
- 링크 작업 중복 키에는 정규화된 주소·실제 문구·채널과 블로그 사진 내용만 포함합니다. 기존 성공·불확실 결과는 자동 재전송하지 않습니다. 게시 시도 전 실패만 명시적으로 다시 준비할 수 있습니다.
- 이전 사진·영상 작업과 원본·중복 키·게시 결과는 보존됩니다. 기본 운영 모드에서는 이전 미디어 작업을 조회만 허용하고 변환·재시도·전송은 차단합니다. 보관함의 숨기기·복원·페이지 이동·재로그인은 계속 지원합니다.
- Instagram 준비 도우미는 별도 창에서 제목·설명·해시태그를 정리하고 복사합니다. 메인 작성 내용을 유지하며 외부 창으로 opener를 전달하지 않습니다. Meta Business Suite에서 계정·파일·게시 유형을 직접 선택하고 문구를 붙여 넣어 최종 게시합니다. 파일/문구 자동 전달과 Instagram API 게시를 제공하지 않습니다.
- 로그인은 서버의 scrypt 검증, HttpOnly/SameSite=Strict·운영 Secure 쿠키, 30분 만료, 실패 제한, 세션 교체·로그아웃을 유지합니다. 서버 재시작 후 재로그인이 필요합니다. 관리자 API·사진·Instagram 도우미 HTML은 로그인 전 차단합니다.

## X 공식 API 자동화

X는 기존 OAuth 1.0a 네 개 키의 HMAC-SHA1 서명 또는 OAuth 2.0 사용자 토큰을 지원합니다. OAuth 2.0 갱신은 기존 offline.access grant와 별도 암호화 키·영구 저장소로 회전된 토큰을 보관하고 동시 갱신을 하나로 묶습니다. 새 grant는 자동 생성하지 않습니다.

**X 연결 확인**은 명시적 비용 안내와 확인 후 계정 조회 GET만 실행하며 갱신·게시를 실행하지 않습니다. URL 포함 글 생성의 현재 US$0.20와 조회 비용을 안내하고, 실제 비용 상한은 X Developer Console에 둡니다. 비용 확인값은 숫자 예산이 아닙니다. 로그인·Origin·CSRF·60초 제한, 오류 비밀 제거, 불확실한 게시·갱신 재시도 차단을 검증합니다.

설정 이름·기존 인증 재사용·안전한 갱신 저장·운영 확인 순서는 [X-OPERATIONS.md](X-OPERATIONS.md)를 확인하세요. 코드 검증은 모의 API만 사용합니다. 코드 배포와 실제 X 인증·유료 조회·게시 승인은 별도로 관리합니다. 배포 초기에는 X 게시와 비용 확인 스위치를 모두 false로 유지합니다.

## Facebook 연결 진단

관리자에서 **페이스북 연결 확인**을 누르면 기존 서버의 Page 인증정보로 `GET /me?fields=id,name` 한 번만 요청합니다. 새 토큰·권한을 만들거나 게시·재게시하지 않습니다. 대상 Page ID는 `1387247911137772`이며, 인증 성공도 글쓰기 권한이나 실제 게시 성공을 증명하지 않습니다.

로컬 진단 API는 `POST /api/admin/facebook/check`이고 입력은 빈 JSON 객체만 허용합니다. 로그인·동일 Origin·CSRF 검사를 적용하며, 모든 관리자 세션을 합쳐 60초에 한 번만 허용하고 진행 중 중복 요청도 차단합니다. 외부 Meta 요청은 GET만 사용합니다. 실패한 진단도 제한에 포함됩니다.

화면·작업 이력·실패 로그에는 확인 단계, HTTP 상태, 정수인 Meta `code`/`error_subcode`, 허용한 오류 `type`만 남깁니다. `sns_job_failed` 로그에는 작업 UUID와 고정 채널·내부 오류 분류도 포함됩니다. 원문 오류 메시지·응답 본문·URL·헤더·토큰은 기록하지 않습니다. 기존에 저장되지 않은 과거 Meta 숫자 코드는 복구할 수 없습니다.

Facebook 링크 작업의 준비된 파일 0개는 정상입니다. Page 인증 단계 실패이고 게시 시도 전이라면 명시적으로 다시 준비할 수 있지만, 게시 시도 이후 결과가 불확실하면 기존 중복 방지에 따라 재전송을 차단합니다. 인증 만료와 권한 부족은 숫자 진단 또는 안전한 플랫폼 경로에서 확인해야 하며, 단순 분류만으로 만료를 단정하지 않습니다.

## 작업·보관함 목록

작업 이력·보관 파일·휴지통은 체크박스, 날짜, 채널/파일 유형, 제목/파일명, 상태와 **상세** 버튼을 짧은 행으로 표시합니다. 긴 제목과 파일명은 행에서 줄임 표시하고 상세에서 전체 내용을 확인합니다. 긴 본문·오류·이미지는 기본으로 접혀 있으며 **상세 / 접기**로 열고 닫습니다. 이미지는 상세를 처음 펼칠 때만 불러옵니다.

행 선택과 상세 펼침은 독립적입니다. 목록 새로고침은 같은 항목의 선택과 펼침을 유지하고, 보관/휴지통 탭·페이지를 바꾸면 선택을 초기화합니다. 선택 전송 확인, 블로그 원고 복사, 원본 다운로드, 휴지통 이동·복원과 기존 중복 방지는 유지합니다. 휴지통의 작업 행은 원래 작업 상태도 표시합니다. 모바일에서는 날짜·채널을 제목 아래에 배치하며 체크박스는 16px로 고정합니다.

## 검증

```powershell
node admin-ui/scripts/check.mjs
node --test admin-ui/tests/*.test.mjs
# Playwright 모듈과 Chromium 경로를 환경에 맞게 지정한 뒤:
node admin-ui/scripts/browser-test.mjs
node admin-ui/scripts/link-introduction-browser-test.mjs
node admin-ui/scripts/catalog-browser-test.mjs
node admin-ui/scripts/compact-lists-browser-test.mjs
node admin-ui/scripts/x-browser-test.mjs
```

이전 `media-selection-browser-test.mjs`와 `server-browser-test.mjs` 진입점은 새 링크 검사로 연결됩니다. `media-test.mjs`는 남아 있는 이전 변환 모듈용 검사이며 현재 링크 흐름의 필수 검사가 아닙니다.

테스트는 임시 저장소·합성 비밀번호·공식 API 형식의 모의 응답·모의 게시만 사용합니다. 새 브라우저 검사는 영상 도구 호출 0회, 실제 SNS 요청 0회, 임의 외부 브라우저 요청 0회를 확인합니다. 홈페이지 API 보존·기존 변환 모듈·원자적 저널·재시작·휴지통은 단위/통합 회귀 검사로 확인합니다. 최종 캡처와 브라우저 근거는 `test-results/link-introduction/`, `test-results/catalog/`에 생성합니다.

실제 사용자 YouTube URL 조회, 운영 Facebook/X 인증·권한·비용, 실제 게시 결과는 아직 검증하지 않았습니다. mock 성공을 서비스 검증으로 해석하지 않습니다.
