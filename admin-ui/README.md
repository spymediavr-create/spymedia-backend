# SpyMedia SNS 자동페이지

기존 `spymediavr-create/spymedia-backend`의 YouTube 조회 API에 관리자 화면과 SNS 전송 서버를 추가했습니다. 기준 커밋은 `f8cd849dea46d1aef73e7f6f640cbc49d344012f`입니다. 기존 공개 API·홈페이지 파일·Render 요금 및 설정 선언은 보존합니다.

## 로컬 화면 확인

```powershell
Set-Location '<spymedia-backend checkout 경로>'
node admin-ui/server.mjs
```

http://127.0.0.1:4310/admin/login 에서 **화면 미리보기**를 선택하세요. 별도 미리보기 서버는 루프백에만 바인딩하며 인증 성공을 가장하지 않습니다. 파일은 브라우저 메모리에만 있습니다. 기존 `npm start` 서버에는 미리보기를 허용하지 않습니다.

## 구현

- Canva에 맞춘 로그인·관리자 화면, 영상/이미지, 제목/설명, 지역/촬영유형, **해시태그 추천**과 수동 수정, 정확한 다섯 채널 카드 이름.
- 서버에서 scrypt 비밀번호 검증, HttpOnly/SameSite=Strict 세션, 운영 HTTPS Secure 쿠키, 30분 만료, 로그인 실패 제한, 세션 교체·로그아웃, Origin 및 CSRF 검증. 세션은 단일 인스턴스 메모리에 있으며 재시작 시 다시 로그인합니다.
- 원본 스트리밍 업로드, 크기·파일 시그니처·FFprobe 검증, UUID 경로, 내용 해시 중복 제거, 저장 용량 상한. 원본은 공개 정적 디렉터리 밖에 보관합니다.
- FFmpeg로 JPEG / H.264·AAC MP4 변환, 메타데이터 제거, Instagram 사진 1080×1350 및 영상 1080×1920, 다른 채널 최대 1920×1080. 비율을 유지하며 Instagram에는 여백을 넣습니다. 자동 자르기는 하지 않습니다.
- 채널별 변환 결과와 실제 전송 텍스트 미리보기, YouTube 공개 범위·아동용 여부 명시, 선택 작업 전송. 변환은 전송 전 단계이며 외부 게시 API를 호출하지 않습니다.
- 영구 JSON 작업 기록과 단일 작업 실행 순서. 동일 내용·원본·채널 작업을 재사용합니다. 변환·전송 상태, 실패 원인, 채널별 성공을 보존합니다. 전송 결과가 불명확하거나 전송 중 재시작하면 `unknown`으로 멈추고 재게시하지 않습니다. 게시 시도 전 실패만 다시 준비할 수 있습니다.
- Instagram Login 컨테이너 생성·처리 상태 확인·발행·결과 확인; Facebook Page 사진/다중 사진/영상 전송 및 결과 확인; X OAuth 사용자 토큰의 미디어 분할 업로드·처리 확인·글 생성; YouTube OAuth 갱신 토큰과 resumable 업로드.
- X는 사용자가 기존 API 연결·테스트 완료를 확인했습니다. 이 checkout/프로세스에서는 기존 구성을 읽을 수 없고 Render 설정은 미확인입니다. 새 X API 값이나 설정을 다시 요구하지 않으며 기능은 유지합니다.
- 매 전송 전 지정 계정을 확인합니다. Facebook 개인 프로필은 거절합니다. 설정 존재는 계정 검증 완료를 뜻하지 않으며 전송이 시작될 때 실제 확인합니다.
- 블로그는 원고·태그와 원본 다운로드, 영상에서 추출한 이미지를 준비하고 사용자가 네이버에서 최종 게시합니다. 네이버 API 게시나 브라우저 매크로는 없습니다.

## 운영 활성화 전 확인

기본값은 관리자 인증 및 SNS 전송 비활성입니다. 인증·영구 저장소·파일 처리 도구가 준비되지 않으면 서버가 요청을 거절합니다. 현재 PC에 Render API나 로그인된 브라우저 제어 도구가 없다는 사실만으로 Render 서비스의 설정 유무를 판단하지 않습니다.

설정할 정확한 항목, 계정/권한 승인 범위와 안전한 입력 위치는 [OPERATIONS.md](OPERATIONS.md)를 확인하세요. 새 실사용 자격증명이나 OAuth 권한은 이 코드 작업에서 발급하지 않았습니다. 비밀번호·토큰·시크릿을 채팅, 코드, Git 또는 로그에 넣지 마세요.

이 구현의 저장소는 **이미 존재하는 영구 마운트와 단일 인스턴스**가 확인될 때 사용합니다. 일반 Render 파일시스템에는 저장하지 않습니다. 기존 DB/객체 저장소만 있는 경우에는 해당 저장소 어댑터를 먼저 연결해야 합니다. 새 디스크·요금제·유료 서비스는 자동 생성하지 않습니다. 백업과 원본 정리는 운영자가 계획해야 하며 자동 삭제하지 않습니다. 사용자가 확인한 영구 저장 용량에 맞춰 상한을 설정하세요.

## 검증

```powershell
node admin-ui/scripts/check.mjs
node --test admin-ui/tests/*.test.mjs
node admin-ui/scripts/browser-test.mjs
# FFMPEG_PATH / FFPROBE_PATH 설정 후 실행
node admin-ui/scripts/media-test.mjs
node admin-ui/scripts/server-browser-test.mjs
```

서버 테스트는 기존 package.json 의존성이 필요합니다. 브라우저 테스트는 실행 중인 미리보기 서버와 Playwright/Chromium이 필요하며 번들 모듈은 `PLAYWRIGHT_MODULE`, 브라우저는 `PLAYWRIGHT_BROWSERS_PATH`로 지정할 수 있습니다. Node 24.19.0에서 검증했고 기존 Node 18.x 선언은 변경하지 않았습니다.

테스트는 프로세스 안의 가상 자격증명, 임시 저장소, 합성 미디어와 모의 SNS API를 사용합니다. 실제 사용자 로그인·OAuth 권한 생성·SNS 게시를 실행하지 않습니다. Windows 테스트 바이너리로 합성 영상·이미지의 실제 FFmpeg 변환 10개와 인증 화면→업로드→변환→모의 전송→중복 방지→로그아웃 브라우저 흐름 6개를 확인했습니다. 운영 Render 도구와 승인 콘텐츠의 실제 SNS 게시 테스트는 별도 수행해야 합니다. Meta 직접 문서 일부는 읽기 제한으로 현재 계약을 끝까지 확인하지 못했으므로 앱의 지원 Graph 버전을 지정하고 승인된 콘텐츠로 마지막 검증해야 합니다.

브라우저 캡처와 요청 검사 결과는 Git 제외 디렉터리 `test-results/`에 있습니다. 로컬 인수인계 기록과 개인 Library 참조도 Git에서 제외합니다. 테스트용 인증 값은 프로세스에서 일시적으로 만들며 코드에 저장하지 않습니다.
