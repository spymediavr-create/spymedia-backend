# SNS 계정 관리 탭

기존 관리자에서 별도 외곽 카드였던 공개 웹 검색과 저장 후보를 **SNS 계정 관리** 카드 안의 **새 계정 검색 / 저장 후보**로 통합합니다. 두 기능의 API·인증·저장소·Brave 설정과 기존 수동 처리 버튼은 바꾸지 않습니다. 자동 팔로우·일괄 프로필 열기·새 완료 표시 기능은 추가하지 않습니다.

## 화면과 데이터 수명

| 동작 | 임시 검색 | 저장 후보 |
|---|---|---|
| 두 화면 탭 전환 | 결과·체크·검색 조건을 메모리에 유지. 검색 호출·저장·자동 이동 없음 | 목록·체크·필터·편집 초안 유지. 추가 저장 없음 |
| 새 검색 / 결과 지우기 | 기존 수명 규칙으로 결과·체크 삭제 | 변경 없음 |
| 첫 조회 후 15분 | 검색 화면이 숨겨져 있어도 삭제. 탭 전환은 타이머를 연장하지 않음 | 변경 없음 |
| 새로고침 / 페이지 떠나기 | 결과·체크 삭제 | 서버에 저장된 체크·메모·상태 유지. 저장하지 않은 초안의 영구 보존은 보장하지 않음 |
| 인증 만료 | 결과·체크 삭제, 검색 차단 | 쓰기 차단, 현재 페이지의 초안 유지, 재로그인 안내 |

기본 화면은 새 계정 검색입니다. 기존 `#sns-candidates` 링크는 저장 후보를 열고 `#sns-temporary-search` 링크는 검색 화면을 엽니다. 탭 선택을 브라우저 저장소에 기록하지 않으며, 탭 클릭은 URL에 검색어·선택 결과를 넣지 않습니다. 초기 관리자 상태 조회와 기존 후보 목록의 최초 읽기는 이전과 같습니다. 화면 탭을 바꿀 때 추가 검색·후보 API 요청을 보내지 않습니다.

두 화면은 DOM을 제거하지 않고 `hidden`으로 전환합니다. 각 기능이 자신의 상태와 삭제 타이머를 계속 관리하며, 검색 결과나 임시 선택을 저장 후보 양식으로 복사하지 않습니다. SNS 하위 선택 버튼과 페이지 이동도 각 화면의 기존 동작을 유지합니다.

## 접근성과 모바일

`tablist` / `tab` / `tabpanel`, `aria-controls`, `aria-labelledby`, `aria-selected`를 연결했습니다. 선택된 탭만 Tab 키의 진입점이며 왼쪽·오른쪽 화살표는 순환, Home·End는 처음·끝 탭을 엽니다. 화면 전환은 네트워크 요청 없이 즉시 이루어집니다. 숨겨진 화면의 컨트롤은 키보드·접근성 탐색에서 빠지며, 선택된 탭 다음에는 해당 화면과 내부 컨트롤로 이동합니다. 기존 fragment 링크도 대상 화면을 먼저 연 뒤 표시합니다.

360/390px에서 가로 넘침을 검사하고 두 탭은 최소 44px 높이의 터치 영역을 유지합니다. 한 개의 공통 제목·외곽 카드와 각 화면의 도구줄을 사용하고 중복 제목·설명을 줄였습니다.

## 검증 명령

```bash
npm run admin:check
npm run admin:test
CHROMIUM_EXECUTABLE=/usr/bin/chromium node admin-ui/scripts/temporary-search-browser-test.mjs
CHROMIUM_EXECUTABLE=/usr/bin/chromium node admin-ui/scripts/candidates-browser-test.mjs
CHROMIUM_EXECUTABLE=/usr/bin/chromium node admin-ui/scripts/link-introduction-browser-test.mjs
```

검색 브라우저의 11개 흐름에는 탭의 ARIA 연결·키보드·초점·기존 fragment, 임시 선택과 후보 편집 초안의 분리·보존, 조회 도중 전환, 숨겨진 검색의 만료, 양쪽 화면의 인증 만료와 모바일을 포함합니다. 별도 임시 fixture와 모의 응답만 사용하고 기존 후보 저널 바이트 동일성 및 실제 외부 요청·SNS 호출 0건을 검사합니다. 운영 DB에 테스트 데이터를 넣지 않습니다. 운영 관리자 세션·실제 Brave 인증·실제 휴대폰 확인은 별도 검증 범위입니다.
