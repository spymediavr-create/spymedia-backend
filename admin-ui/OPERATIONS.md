# SNS 링크 소개·Instagram·블로그 운영 안내

메인 관리자의 Instagram 기본 흐름은 사진/릴스를 선택하고 원본과 문구를 저장한 뒤 공식 게시 API로 전송하는 방식이다. 계정·게시 권한과 저장된 파일·문구를 확인한 뒤 사용자가 전송한다. 서버 재인코딩은 하지 않으며 Meta Business Suite 도우미는 접힌 보조 영역에 보존한다. 자세한 내용은 [Instagram 운영 안내](INSTAGRAM-OPERATIONS.md)를 따르며, 아래 Facebook·X의 YouTube 링크 방식과 블로그 소개 사진 기능은 유지한다.

기존 대상은 [Render 서비스](https://dashboard.render.com/web/srv-d81bo0rtqb8s738pcv6g), `spymediavr-create/spymedia-backend`의 main, https://spymedia-backend.onrender.com 입니다. 기존 디스크 `/spymedia` 10GB, 데이터 `/spymedia/sns`, 단일 인스턴스와 홈페이지 API·자동 실행 설정을 보존합니다. 요금제·디스크·환경변수 값을 임의 변경하지 않습니다.

main push는 자동 배포를 시작합니다. 승인 전에는 push·배포·서비스 재시작을 하지 않습니다. 진행 중인 기존 영상 작업이 있으면 배포 전에 상태를 확인하고 중단 영향을 설명합니다. 배포 승인 후 기존 서비스의 코드만 반영하고 실제 SNS 게시·인증 설정·요금은 변경하지 않습니다.

## 새 링크 흐름

1. 사용자가 직접 YouTube에 본편을 업로드합니다.
2. 관리자에서 주소로 공개 제목·설명·썸네일을 조회하고 적용·수정합니다.
3. Facebook·X 링크 소개와 블로그 원고를 준비합니다. 준비는 게시를 실행하지 않습니다.
4. 사용자가 정확한 문구·주소·채널을 확인한 뒤 선택한 Facebook·X 작업을 전송합니다.
5. 블로그는 준비 자료를 이용해 사용자가 최종 게시합니다. Instagram은 메인 영역에서 사진/릴스를 선택하고 원본 검사·저장, 작업 준비, 계정·게시 권한 확인, 저장된 작업 최종 확인 후 직접 전송합니다. 별도 사진 도우미와 Meta Business Suite 보조 도우미도 유지합니다.

YouTube 조회에는 기존 `YOUTUBE_API_KEY`만 재사용합니다. 키 값은 모델·채팅·로그로 전달하지 않습니다. 새로운 YouTube 업로드 OAuth 권한·갱신 토큰은 이 흐름에서 생성하지 않습니다. 조회 준비 여부만 인증된 상태 API에 노출합니다.

공식 조회 API는 15초·응답 128KiB·리다이렉트 0회로 제한합니다. 썸네일은 동일 영상 ID의 `https://i.ytimg.com/vi/<ID>/<이름>.jpg`만 허용하며 15초·2MiB·리다이렉트 0회로 가져옵니다. 썸네일 실패 시 문구만 제공하고 기존 작성 내용은 보존합니다. 휴지통에 있는 같은 썸네일을 자동 복원하지 않습니다.

사진은 JPG/PNG/WebP, 8MiB, 가로·세로 4096px 이내·총 1,600만 화소 이하로 받습니다. 스트리밍 저장·파일 헤더/치수 검증·내용 해시 중복 제거를 수행합니다. 전체 픽셀 디코딩과 리사이즈·EXIF 제거는 하지 않으며 블로그 다운로드는 원본입니다. 링크 소개는 영상 업로드·변환을 사용하지 않습니다. 릴스는 별도 업로드 경로에서 규격을 통과한 원본을 보관합니다.

## 네이버 블로그 반자동 준비

메인 관리자의 블로그 전용 영역에서 공통 제목·설명·해시태그·촬영 정보를 원고로 가져온 뒤 블로그용 제목과 본문을 따로 편집한다. 공통 내용을 나중에 변경해도 편집한 블로그 원고를 덮어쓰지 않는다. 별도 AI 생성 서비스는 호출하지 않으며 입력되지 않은 촬영 실적이나 조건을 만들어 넣지 않는다. YouTube 주소는 선택사항이다.

작업실 상단 **유튜브 영상 링크**에서 영상 주소를 직접 넣거나 **공통 영상 주소 가져오기**로 주소만 가져올 수 있다. 제목·본문·사진 선택은 유지된다. 일반 영상·Shorts·youtu.be 공유 주소를 검증해 정규 영상 주소로 저장하며, **영상 링크 복사**는 주소만 복사한다. **본문 복사**와 TXT에는 영상 주소가 함께 포함된다. **유튜브에서 영상 열기**는 검증한 영상 주소만 새 탭으로 연다. 영상 파일 다운로드·업로드·변환이나 자동 재생은 하지 않으며, 네이버의 링크 표시 형식은 네이버 편집기에서 확인한다.

제목 복사, 본문 복사, 전체 원고 텍스트 내려받기, 사진 순서 정리·제외·개별 원본 내려받기를 제공한다. 사진은 위 소개 사진에서 선택하며 기존 원본 파일을 그대로 사용한다. 복사 권한이 거절되면 선택 가능한 텍스트로 수동 복사를 안내한다.

**블로그 초안 저장**은 기존 관리자 인증·Origin·CSRF 검사를 거쳐 `POST /api/admin/jobs`의 `type: blog-draft`, `channels: [blog]`로 원고와 사진을 기존 영구 저장소에 보관한다. 제목 최대 200자·본문 5,000자·태그 30개·사진 0~10장을 받는다. 영상 파일이나 변환 도구는 사용하지 않는다. 저장 당시 내용을 독립 기록으로 보관하고 동일 내용의 재요청은 같은 기록을 돌려준다. 저장된 초안은 다시 열어 수정할 수 있으며 수정 후 저장은 새 기록이다. 로그인 만료나 저장 실패가 발생해도 화면의 편집 내용을 유지한다.

블로그 열기는 사용자가 확인한 `https://blog.naver.com/spymedia`를 새 탭으로 연다. 제목과 본문을 각각 붙여넣고 사진을 추가한 뒤 네이버에서 사용자가 최종 발행한다. 글쓰기 화면 자동 조작, 로그인 정보 수집, 공개 게시 요청, 발행 결과 자동 동기화는 없다. 복사·저장은 게시 성공으로 표시하지 않는다. [네이버 블로그 글쓰기 API 종료 안내](https://developers.naver.com/notice/article/7527)를 따른다.

기존 `type: link`의 블로그 원고와 사진은 보존한다. Facebook·X 링크 작업의 YouTube 필수 조건과 명시적 전송 절차, Instagram Meta 연결·사진·원본 릴스 기능은 유지한다.

## 관리자와 영구 저장소

기존 `APP_MODE=authenticated`, `ADMIN_LOGIN_ID`, `ADMIN_PASSWORD_SCRYPT`, `PUBLIC_ORIGIN` 설정을 유지합니다. 운영 쿠키는 Secure/HttpOnly/SameSite=Strict이고 세션은 30분입니다. 로그인 전 관리자 HTML/API·사진·Instagram 도우미 접근을 서버에서 차단하고 변경 요청은 Origin과 CSRF를 검사합니다. JSON 요청 최대 크기는 64KiB이고 필드별 길이 검증을 추가로 적용합니다.

기존 `SNS_DATA_DIR`, `SNS_STORAGE_PERSISTENCE=confirmed`, `SNS_SINGLE_INSTANCE=confirmed`를 유지합니다. 저장소는 체크아웃/public 밖의 기존 영구 마운트여야 합니다. `SNS_MAX_STORAGE_BYTES`는 기존 공간 안의 상한입니다. 휴지통은 목록에서 숨기는 기능으로 실제 바이트는 삭제하지 않으며 공간을 비우지 않습니다. 새 디스크나 객체 저장소를 만들지 않습니다.

작업은 영구 JSON 저널에 기록합니다. 선택 전송 전 체크포인트를 저장하고 게시 ID 응답을 받은 후 채널에서 확인합니다. 외부 POST 결과가 불확실하거나 전송 중 재시작하면 `unknown`으로 정지하며 자동 재전송하지 않습니다. 결과 확인 후 수동 조정 API는 아직 없으므로 저널을 임의 편집하지 않고 후속 복구 작업으로 처리합니다.

Facebook 권한은 기존 `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`와 Page 콘텐츠 접근을 확인합니다. 개인 프로필 `100069643772419`는 대상이 아닙니다. 필요성이 확인되지 않은 `business_management` 권한을 추가하지 않습니다. 링크 소개에는 미디어 서명 키와 영상 업로드 URL이 필요하지 않습니다. 기존 `MEDIA_SIGNING_KEY`와 이전 미디어 접근 경로는 변경하지 않습니다.

사용자는 이전 X API 연결·테스트를 확인했습니다. 현재 코드와 운영 인증 방식의 호환, 쓰기 권한·잔액·실제 콘솔 비용 상한은 별도로 확인해야 합니다. X 연결 진단·OAuth 1.0a 서명·OAuth 2.0 암호화 갱신 저장·비용 안내의 세부 내용은 [X-OPERATIONS.md](X-OPERATIONS.md)를 따릅니다. 설정이 불완전하면 전송 선택을 차단하고 준비·미리보기만 허용합니다. 값과 새 인증 권한을 모델에 요청하지 않습니다. 공식 사용자 인증 요구사항을 운영 연결 시 확인합니다.

`SNS_PUBLISH_ENABLED`는 기존 전체 전송 스위치이며 코드 기본값은 false입니다. 설정 존재는 인증 검증 완료를 뜻하지 않습니다. 지정 계정 조회와 게시 ID 확인은 실제 전송 요청에서 이루어집니다. 이번 로컬 테스트는 전부 모의 응답이므로 실제 서비스 검증이 아닙니다.

Meta 앱 `1577001733647513`, Instagram Login 하위 앱 `1030189823411067`의 운영·심사·토큰 갱신과 과거 노출 토큰 폐기 확인은 완료되지 않았습니다. 별도 도우미가 이 상태를 해결하거나 검증했다고 표시하지 않습니다. 신규 인증과 비밀 저장이 필요하면 사용자 승인 및 안전한 플랫폼/Render 입력 경로로만 진행합니다.

## Facebook 연결 진단

관리자에서 **페이스북 연결 확인**을 누르면 기존 서버의 Page 인증정보로 `GET /me?fields=id,name` 한 번만 요청합니다. 새 토큰·권한을 만들거나 게시·재게시하지 않습니다. 대상 Page ID는 `1387247911137772`이며, 인증 성공도 글쓰기 권한이나 실제 게시 성공을 증명하지 않습니다.

로컬 진단 API는 `POST /api/admin/facebook/check`이고 입력은 빈 JSON 객체만 허용합니다. 로그인·동일 Origin·CSRF 검사를 적용하며, 모든 관리자 세션을 합쳐 60초에 한 번만 허용하고 진행 중 중복 요청도 차단합니다. 외부 Meta 요청은 GET만 사용합니다. 실패한 진단도 제한에 포함됩니다.

화면·작업 이력·실패 로그에는 확인 단계, HTTP 상태, 정수인 Meta `code`/`error_subcode`, 허용한 오류 `type`만 남깁니다. `sns_job_failed` 로그에는 작업 UUID와 고정 채널·내부 오류 분류도 포함됩니다. 원문 오류 메시지·응답 본문·URL·헤더·토큰은 기록하지 않습니다. 기존에 저장되지 않은 과거 Meta 숫자 코드는 복구할 수 없습니다.

Facebook 링크 작업의 준비된 파일 0개는 정상입니다. Page 인증 단계 실패이고 게시 시도 전이라면 명시적으로 다시 준비할 수 있지만, 게시 시도 이후 결과가 불확실하면 기존 중복 방지에 따라 재전송을 차단합니다. 인증 만료와 권한 부족은 숫자 진단 또는 안전한 플랫폼 경로에서 확인해야 하며, 단순 분류만으로 만료를 단정하지 않습니다.

## 이전 영상 작업 보존

`SNS_LEGACY_PREPARATION_ENABLED`는 기본 false입니다. 새 화면은 이전 사진·영상 작업을 읽기 전용으로 보여주고 기존 원본·이력·결과·중복 키를 그대로 보존합니다. 이전 작업의 준비·재시도·전송은 기본 모드에서 차단합니다. 상태 조회·사진 보관·링크 준비·링크 재시도는 FFmpeg/FFprobe를 호출하지 않습니다.

이전 변환 모듈과 커넥터는 회귀 검사용으로 남아 있습니다. 테스트에서만 명시적으로 legacy 플래그를 활성화합니다. 기존 Render 메모리 초과 재시작 문제가 해결됐다고 단정하지 않으며 운영에서 이전 영상 경로를 재활성화하거나 요금제를 변경하지 않습니다.

## 배포 이후 별도로 확인할 것

승인된 배포 이후 관리자 재로그인, 홈페이지 조회 API, 기존 보관함·이력, 사용자 YouTube 주소 가져오기, 메타데이터와 썸네일을 확인합니다. 실제 Facebook/X 전송에는 승인된 문구·주소·채널을 먼저 확정해야 합니다. 실제 API 인증·권한·비용·결과 검증은 로컬 mock 테스트와 별도로 보고합니다.
