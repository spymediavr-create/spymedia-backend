# SNS 계정 후보 체크 — 구현·검토 안내

이 기능은 기존 `/admin`의 후보 조사·선택·수동 기록 기능입니다. 기존 Render 서비스, 관리자 로그인, 영구 저장소를 재사용합니다. 최초 구현과 후속 지역·페이지 개선은 작업 브랜치에서 검증하고, 사용자 승인 범위에서 기존 서비스에 반영합니다. 환경변수나 요금제는 바꾸지 않습니다.

## 사용 순서

1. 관리자 상단 **SNS 계정 관리 → 저장 후보** 탭에서 Instagram / Facebook / X / 네이버 블로그를 선택합니다. 초기 목록은 비어 있습니다. 같은 카드의 **새 계정 검색**은 임시 목록이며 저장 후보와 별개입니다. 탭 전환은 저장 후보의 선택·필터·작성 중인 내용을 유지합니다.
2. **후보 추가**에서 **계정/기관·업체명**, HTTPS 프로필 URL을 입력합니다. 업종·지역·추천 이유·메모는 선택 입력입니다.
3. 업종은 **공공기관·지자체 / 부동산 / 영상제작 / 건설 / 행사기획·운영 / 기타** 중 선택하거나 **여행사** 같은 임의 업종을 직접 입력합니다. 지역은 별도 필드에서 **전국·시도·권역·시흥·영흥도**를 선택하거나 직접 입력합니다. 영흥도를 기관명이나 업종으로 자동 분류하지 않습니다.
4. **저장 후보 검색**에 임의 키워드를 입력하고 필요하면 업종·지역·처리 상태를 조합한 뒤 **필터 적용**을 누릅니다. SNS 선택도 함께 적용됩니다. 업종은 일치 검색입니다. 지역은 아래 권역·약칭 규칙과 자유 입력을 지원하고, 키워드는 포함 검색 및 정확한 지역 약칭을 지원합니다. 키워드는 명칭·업종·지역·추천 이유·메모·프로필 URL에서 찾습니다.
5. 새 계정을 조사하려면 키워드와 지역을 입력한 뒤 **외부 검색 열기**를 누릅니다. 선택한 SNS 도메인을 포함한 Google 검색을 새 창으로 엽니다. 검색 결과를 관리자 내부로 수집하지 않습니다. 적합한 계정의 프로필 URL을 확인하고 직접 후보에 추가합니다.
6. **프로필 새 창에서 열기**로 직접 확인하고 개별 체크 또는 **이 페이지 전체 선택**을 누릅니다. **10개씩 표시되는 하단 숫자 페이지**나 이전·다음으로 이동할 수 있습니다. 현재 페이지·전체 건수·총 페이지 수를 표시하며, 많은 페이지는 처음·끝·현재 주변 번호와 생략부호로 줄입니다. 필터·SNS 변경은 첫 페이지로 이동합니다. 선택 상태는 즉시 서버에 저장되며 새로고침·재로그인·서버 재시작 후 유지됩니다.
7. 개별 처리 상태 또는 일괄 버튼으로 **제외**, **팔로우 완료 (수동 기록)**, **검토 중**을 지정합니다. 일괄 변경은 **현재 페이지에서 선택한 후보만** 대상으로 합니다. 다른 페이지·필터·SNS에서 저장한 선택은 유지됩니다.
8. **정보·메모 수정**에서 정보를 수정합니다. 팔로우 완료 기록은 사용자가 SNS에서 직접 처리한 내용을 기록한 것이며, 실제 팔로우 여부는 자동 확인하지 않습니다. 상태와 체크는 독립적입니다. 제외한 후보는 제외 필터에서 다시 검토 중으로 돌릴 수 있습니다.

체크·저장·수동 상태 변경 자체는 SNS의 팔로우나 게시 상태를 바꾸지 않습니다. 현재 페이지에서 선택한 Instagram 프로필은 별도 브라우저 도구로, X 프로필 한 개는 공식 API 검토·실행으로 연결할 수 있습니다. 이는 수동 완료 기록과 별개이며 결과에 따라 그 기록을 자동 수정하지 않습니다. [팔로우 도구의 설치·검증 범위](FOLLOW-TOOLS.md)를 확인하세요. 자동 맞팔·DM·SNS 로그인 정보 입력 기능은 없습니다.

## 지역 선택과 매칭

지역 옵션은 총 27개입니다. 전국, 수도권·강원권·충청도·전라도·경상도·제주권, 시도명, 시흥·영흥도를 제공합니다. 모든 입력란은 자유 입력도 유지합니다.

[행정안전부 지자체 누리집](https://www.mois.go.kr/frt/sub/a04/localGovernment/screen.do)과 [정부24 지방자치단체 목록](https://www.gov.kr/portal/orgInfo/orgmapr)을 2026-10-15 확인했습니다. 현재 공식 목록은 **16개**로, 광주·전남을 **전남광주통합특별시**로 표시합니다. 요청하신 익숙한 17개 지역을 모두 검색할 수 있도록 **광주광역시·전라남도**도 통용 지역명으로 남겼습니다. 이 둘을 현재 별도 광역자치단체라고 표시하지 않습니다.

현재 시도 옵션: 서울특별시, 부산광역시, 대구광역시, 인천광역시, 대전광역시, 울산광역시, 세종특별자치시, 경기도, 강원특별자치도, 충청북도, 충청남도, 전북특별자치도, 경상북도, 경상남도, 제주특별자치도, 전남광주통합특별시입니다.

| 선택 | 매칭 |
|---|---|
| 전국 또는 빈 지역 | 지역 제한 없음. 지역이 비어 있는 후보도 포함 |
| 수도권 | 서울·인천·경기, 명시된 수도권, 기존 시흥·영흥도 |
| 강원권 | 강원특별자치도·강원도·강원, 명시된 강원권 |
| 충청도 / 충청권 | 충북·충남·대전·세종, 명시된 충청도·충청권 |
| 전라도 / 호남권 | 전북·전남·광주·전남광주통합특별시, 명시된 전라도·호남권 |
| 경상도 / 영남권 | 경북·경남·부산·대구·울산, 명시된 경상도·영남권 |
| 제주권 | 제주특별자치도·제주도·제주, 명시된 제주권 |

서울/서울시/서울특별시, 충북/충청북도, 강원/강원도/강원특별자치도, 전북/전라북도/전북특별자치도, 제주/제주도/제주특별자치도 등 공식·약칭·이전 명칭을 서로 찾습니다. 정확한 약칭을 저장 후보 키워드로 검색해도 지역 필드와 호환됩니다. 기존 자유 문자열·선택·메모·상태를 저장 시 정규명으로 강제 변환하거나 일괄 수정하지 않습니다.

시흥은 경기, 영흥도는 인천으로 한정 매핑합니다. 다른 시군구의 전체 소속표는 만들지 않았습니다. 예를 들어 `충남 천안시`는 충청도에서 찾지만, `천안시`만 적힌 후보의 소속을 임의 추정하지 않습니다. `경기도 광주시`는 광주광역시로 분류하지 않습니다. 지역 미입력·미상·전국이라고 저장한 후보는 특정 시도/권역에 임의 배정하지 않습니다. `충청권`만 저장한 후보를 충남으로 좁히거나, 통합명만 저장한 후보를 구 광주/구 전남으로 나누지 않습니다.

외부 검색에서 전국은 지역어를 붙이지 않습니다. 권역은 하위 지역을 **OR**로 묶으며, 시도는 공식명과 약칭을 OR로 묶습니다. 예: `여행사 (충청 OR 충북 OR 충남 OR 대전 OR 세종) site:instagram.com`. 검색엔진 새 창만 열며 결과를 수집하지 않습니다.

## 저장·안전성

- 기존 `SNS_DATA_DIR/journal.json`에 선택적 `candidates` 컬렉션을 보관합니다. 기존 `version: 1`, 미디어·게시 작업·결과·중복 키·그 밖의 메타데이터를 보존합니다. 이전 저널에는 후보를 자동 삽입하지 않습니다.
- 기존 30분 관리자 세션과 `Origin`·CSRF·JSON 64KiB 제한을 적용합니다. 별도 SNS 인증정보나 API 키가 필요하지 않습니다. 저장소가 준비되지 않으면 후보 조회·저장을 차단합니다.
- 명칭 120자, 업종·지역 각 100자, 추천 이유 1,000자, 메모 2,000자, 키워드 200자입니다. 필드 타입·허용 상태·예상 밖 필드를 서버에서 검사합니다. 이름과 본문은 HTML로 삽입하지 않습니다.
- 플랫폼에 맞는 공식 도메인의 HTTPS 프로필 경로만 허용합니다. 자격증명·임의 포트·다른 도메인·게시물 경로·단축 링크 등을 차단합니다. URL을 서버에서 가져오거나 DNS 조회하지 않습니다. 추적 쿼리·프래그먼트를 제거하고 X/Twitter, Naver 모바일, Facebook 숫자 ID 등 지원한 별칭을 정규화합니다.
- SNS와 정규화한 프로필 URL 조합으로 중복을 차단합니다. 같은 URL은 제외·완료 상태에서도 재등록하지 않습니다. 후보 수정과 동시 등록에도 같은 규칙을 적용합니다.
- 직렬화된 기존 원자적 저널 저장을 재사용합니다. 후보 저장 실패 시 메모리도 복구합니다. 후보의 `revision`으로 오래된 화면의 덮어쓰기를 막으며 일괄 요청은 전 항목 검증 후 적용합니다. 충돌 시 편집 내용은 현재 화면에 남습니다. 필요한 문구를 보존한 뒤 새로고침하고 해당 후보의 수정 버튼으로 다시 여세요.
- 프로필·외부 검색 링크에 `target="_blank" rel="noopener noreferrer"`를 적용합니다. 검색어와 지역은 고정 HTTPS 검색엔진 URL의 쿼리 값으로 인코딩합니다. 키워드가 URL 호스트나 실행 코드가 되지 않습니다.
- 서버 후보는 최대 2,000개, 화면은 10개씩, API 목록·일괄 요청은 최대 50개입니다. 후보의 영구 삭제·대량 가져오기·CSV 내보내기는 범위에 포함하지 않았습니다.

## API

모든 경로는 인증된 기존 `/api/admin`에 있습니다. 쓰기에는 동일 Origin과 기존 CSRF 토큰이 필요합니다.

| 메서드·경로 | 용도 |
|---|---|
| `GET /api/admin/candidates` | `platform`, `status`, `industry`, `region`, `q`, `offset`, `limit` 조합 목록 |
| `POST /api/admin/candidates` | `platform`, `accountName`, `profileUrl`, 선택적 `industry`, `region`, `reason`, `note`로 후보 추가 |
| `PATCH /api/admin/candidates/:id` | `revision`과 바꿀 필드로 정보·체크·처리 상태 수정 |
| `POST /api/admin/candidates/batch` | `items: [{id, revision}]`, `changes: {selected}` 또는 `{status}`로 일괄 변경 |

`platform`은 `instagram`, `facebook`, `x`, `blog`입니다. `status`는 `pending`, `excluded`, `done`이며 목록의 기본은 `all`입니다. `done`으로 바꿀 때 서버가 `manualDoneAt`을 기록하고 다른 상태로 돌리면 지웁니다. 이 시간은 수동 기록 시간이며 SNS의 실제 팔로우 시각이 아닙니다.

## 실행 가능한 검토

```bash
npm install --no-package-lock
npm run admin:check
npm run admin:test
# Playwright가 있는 로컬 환경에서, 설치된 Chromium 경로에 맞춰:
CHROMIUM_EXECUTABLE=/usr/bin/chromium node admin-ui/scripts/candidates-browser-test.mjs
```

Playwright 모듈 위치는 필요하면 `PLAYWRIGHT_MODULE`로 지정합니다. 새 런타임 의존성은 추가하지 않았습니다. 후보 브라우저 검사는 임시 디렉터리·일회성 합성 관리자·합성 후보만 사용하고 종료 시 임시 저장소를 제거합니다. 프로필·검색 새 창은 로컬 응답으로 대체하여 실제 외부 요청을 보내지 않습니다. 환경변수·운영 저널·운영 인증정보를 읽거나 수정하지 않습니다.

검사 후 `admin-ui/test-results/candidates/`에 `results.json`, `desktop.png`, `mobile-390.png`, `mobile-360.png`가 생성됩니다. 이 디렉터리는 기존 `.gitignore` 정책에 따라 커밋하지 않습니다. 로컬 화면 검토는 이 캡처를 사용하고 운영 적용 여부와 정확한 커밋은 작업 완료 보고에서 확인하세요.

## 검증 결과 (2026-10-15)

- JavaScript 문법 검사 통과.
- Node 24.19.0 전체 단위·통합 테스트: 193개 중 192개 통과, 1개 건너뜀, 실패 0. 건너뛴 항목은 Windows 전용 저널 잠금 재시도입니다. 후보·지역·페이지 테스트는 25개입니다.
- Node 18.20.8 전체 단위·통합 테스트도 193개 중 192개 통과, Windows 전용 1개 건너뜀, 실패 0.
- 신규 Chromium 후보 브라우저 검사: 10개 흐름 통과. 360px·390px 가로 넘침 없음, 프로필과 검색 링크의 opener·referrer·cookie 유출 없음. SNS 제공자 호출·미디어 도구 호출·게시 API 쓰기·실제 외부 요청 모두 0.
- 기존 Facebook/X 링크 소개·블로그 작업실·목록/보관함·미리보기·Instagram 사진/릴스 브라우저 검사 통과. 실제 제공자 응답은 전부 모의 응답입니다.
- Node 18의 기존 릴스 준비 테스트가 브라우저 전역 `File`을 가정하던 문제는 테스트 파일에만 `node:buffer`의 `File` 대체를 넣어 보완했습니다. 서버나 브라우저 구현은 변경하지 않았습니다.

## 남은 한계

저장소에서 후보 계정을 검색하는 기존 검색 API는 찾지 못했습니다. 현재 API 연동은 YouTube 메타데이터와 기존 SNS 게시·인증 진단용입니다. 외부 계정을 관리자 내부 결과로 수집해 바로 선택·저장하려면 별도의 승인된 검색 연동이 필요합니다. 이번 작업은 그 연동이나 새 유료 서비스·키를 만들지 않았습니다.

URL 검사는 형식·공식 도메인·지원 경로의 안전성과 정규 URL 중복만 확인합니다. 계정 실존 여부·소유자·같은 계정의 다른 사용자명/숫자 URL·팔로우 상태는 확인하지 않습니다. 수동으로 링크를 열어 검토해야 합니다. 미저장 편집 내용은 현재 탭 메모리만 사용하므로 탭을 닫거나 새로고침하면 사라집니다. 운영 배포와 실제 휴대폰 Safari/Chrome 확인은 별도 단계입니다.
